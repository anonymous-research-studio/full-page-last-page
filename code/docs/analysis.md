# Analysis

The analysis commands read the per-episode CSV from `fplp score --config <run config>` and write tables to `results/tables/` and figures to `results/figures/`. `make analyze RUN=<run>` runs the standard set (the go/no-go only for the pilot) and stamps the hypotheses CSV with the commit and input checksums; after `fplp disclosure check`, add `LABELS=<consensus labels CSV>` so H5 uses the validated flag or the hand labels. Every command takes `--help`; code is in `src/fplp/analysis/`.

| Command | What it does |
|---|---|
| `fplp hypotheses` | Three families per model: `registered` (H1 to H5 as registered, verdict in 2 of 3 confirmatory models), `amended` (the tests of prereg/AMENDMENT-1.md, verdict in a majority of the confirmatory models where each is estimable, with at least two), and `descriptive` (one-factor arms). Prints the exclusion counts first; sensitivity analyses of the amended family follow (empty replies as stops; without the oldest-date task; without the export task; responsive follow-ups only). `--disclosure-labels` takes the consensus labels from `fplp disclosure check`. On other runs (`--config none`, as `make analyze` does for every run but main), the H rows are descriptive only. |
| `fplp go-no-go` | The pilot decision (prereg section 6): protocol health, plus an RQ1 or RQ2 contrast with a Holm-corrected p below .05 and a difference of at least 15 points, for at least one model. Prints the contrasts and the verdict, nothing else; `--out` writes the contrasts and, beside them, `<out>_models.csv` with each model's empty-reply rate and no-signal rate. |
| `fplp rates` | Per-cell rates for every metric, with bootstrap 95% CIs. Descriptive. |
| `fplp model` | Logistic regression of fetching on signal form. `--spec fixed` (the pre-registered descriptive secondary analysis) treats model and task type as fixed effects with item-clustered SEs (`--by-model` adds form x model); terms hit by separation are marked not estimable. `--spec mixed` is the random-intercept model (variational Bayes), kept for comparison only. |
| `fplp figure` | Headline figure: fetch when needed vs. fetch past a truthful full last page, one point per form. `--facet-models` for one panel per model. |
| `fplp tables` | The paper's results tables as LaTeX rows (`h1_rows`, `a1_rows`, `rq3_rows`, `false_rows`, `verdict_rows`, `reliability_rows`) and Figure 1 (`calibration.pdf`, one panel per model), read from the `fplp hypotheses` CSV, its `_retest.csv` and the scored CSV, so no number in the paper is typed by hand. Columns follow the model order of `--config`. Bold marks a contrast significant after Holm's correction within its part. `make paper` runs it on the main study and copies the files into `../Manuscript/current/tables` and `figures`, where the manuscript picks them up; until then it shows placeholders. `--pilot` writes `pilot_rows.tex` from the `fplp go-no-go --out` CSV and its `_models.csv` (per-model health); `make paper-pilot` copies it into the manuscript, where it is reported as a feasibility check, apart from the results. |
| `fplp robustness` | Amendment 2's exploratory checks on gpt-oss-120b (`configs/runs/robustness.yaml`): C1, whether "when it includes one" in the tool description acts as an end cue (plain minus default wording); C2, whether a total equal to the rows shown reads as "done" when named `total_matches` (minus `total_count`). Paired by item; decides no hypothesis. |
| `fplp reference` | A model's fetch rates beside three scripted reference agents run on the main study's items (`configs/runs/reference.yaml`, free): follows the hint, counts rows, hint-else-count. Descriptive (amendment 2). |
| `fplp multiplicity` | Sensitivity analysis (amendment 2): Holm and Benjamini-Hochberg across every main contrast of the amended family per model, instead of Holm within each part. Changes no verdict. |
| `fplp disclosure` | `sample` draws, for blind labeling (replies shown without their `COMPLETENESS` line; the first author labels all of it, the second a random 100 written to `<out>_second.csv`), 100 incomplete final-line answers (70 where disclosure was warranted), 60 complete ones, and per model 20 matched pairs from the warranted completeness-field cells (from pairs with an incomplete answer in either format) and 10 from the false-signal cells; `check` reports inter-author kappa, forms the consensus, and reports the flag's precision, recall and kappa against it. `screen` (amendment 2) lists incomplete answers the flag did not mark whose reply contains hedging or limiting language, for the labelers to read first; it decides nothing. |
| `fplp stamp` | Writes a JSON file beside a generated output with the commit, whether the code had uncommitted changes, and the SHA-256 of each input, so every number in the paper traces to one commit and one copy of the data. `make analyze` stamps the hypotheses CSV; `fplp tables` writes `provenance.json` beside the tables and figure. |
| `fplp simulate` | Simulated scored data with known effects, for testing and power. |
| `fplp power` | Power of the pilot rule, of H1a, and (`--test amended --rates-file`) the probability of each amended verdict per model. Results are in `docs/power.md`. |

## Statistical conventions

- **Unit of analysis: the item** (task type and item index). Each item is seen under every condition, so contrasts are paired by item. Every model runs each item once; if replicates are added, they are averaged per item before testing, so they count once.
- **Paired tests** (`fplp.analysis.common.paired`), two-sided, chosen by the design rather than the values. When each item has exactly one binary outcome per side (one run per item, one form per side), McNemar's exact test with the Agresti-Min adjusted Wald interval. When a side averages several episodes per item (replicates, or pooled forms), a sign-flip permutation test (10,000 permutations) with a percentile bootstrap interval over items.
- **Fetch tests** (H1 to H4, the go/no-go, the figure) leave out exists items settled by a row on page 1 (`settled_on_page1`, one-page extents only); the amended family and the figure also leave out episodes whose first call asked for fewer rows than the page limit (`own_small_page`).

## Registered and amended tests

Both families are computed and reported; claims rest on the amended tests where they differ (prereg/AMENDMENT-1.md).

| Hypothesis | Registered test | Amended test, and why |
|---|---|---|
| A1 (new, RQ1-RQ2) | none | Each main explicit form: fetch when more rows exist minus fetch on a real last page, paired by item, Holm across forms. A no-signal page looks the same on both extents, so no ceiling or floor in the no-signal rate can decide it; with no signal it is zero in expectation, since nothing on a no-signal page tells the extents apart (reported as a reference; page-1 rows differ between extents for some tasks, and sampling adds noise). |
| H1 | Every form beats no signal (a), and both natural-language pairs beat structured forms (b). | (a) unchanged but not estimable when the no-signal rate exceeds 90%; (b) the information-matched pair only (`nl_note_json` - `total_count`), not estimable when `total_count`'s rate exceeds 90%, with an equivalence test (90% CI within ±10 points) before any "no difference" claim. `cursor_plus_note` - `next_cursor` is reported as adding a range-and-total note. |
| H2 | No signal beats every terminal form on a real last page (a), and the pairs on page-1-sufficient tasks (b). | (a) unchanged but not estimable when the no-signal rate is below 10%; (b) becomes H2b on its own, information-matched pair only. |
| H3 | Pooled fetch rates on the row count's side of 50%. | Estimable only when the model uses the row count without a signal (full vs short first page, no signal); H3a also needs the fetch past a full last page to exceed the fetch past a short last page (truthful signal), so checking every terminal signal does not pass; the reverse direction is H3r, formed after the protocol checks, with the same gate. |
| H4 | False end signals lower fetching below no signal and below truthful signals. | The same behavior as H2a (identical pages); the amended test is its cost: incomplete answers under false end signals minus no signal, with per-task contrasts. |
| H5a | Disclosure rare among incomplete answers in the registered cells (under hand labels, weighted by stratum). | Only where disclosure is warranted (`disclosure_stratum` = `warranted`), from 16 items; the other strata are reported. |
| H5b | Field vs no field, false-signal cells, both answers incomplete. | Warranted cells (no signal, truthful `has_more`), intention to treat (silent incomplete answers, without minus with), and the field must be informative within the no-signal cell (more disclosure on incomplete than complete answers); each part needs 10 items whose outcome can vary. If the flag fails validation, the informativeness part reads the `COMPLETENESS` line alone on every episode, with the labeled version reported beside it, and the intention-to-treat part runs on labeled pairs drawn from those with an incomplete answer in either format, with its difference also rescaled to every warranted pair (changelog, 23 Oct 2026). |

| H6 (amendment 1) | none | Visible conflicts (a false end beside a field that contradicts it) minus the same false ends alone, pooled, sign-flip test; not estimable when fetching under the false ends alone is above 90%. |
| A1u, H1u, H2u (amendment 1) | none | The signal-value test, H1a and H2a for an undocumented interface (the documentation arm on no signal, `has_more` and the note), with the same estimability band. |

Retest reliability: a seeded random 10% of conditions runs twice (arm `retest`); no test uses them, and `fplp hypotheses` reports per model how often the retest matched the first run (share identical, Cohen's kappa) on fetching, evidence seen, correctness and disclosure (also written to `<out>_retest.csv`).

A hypothesis with several parts is "not supported" when any estimable part fails, "supported" when every part is estimable and passes, and "not estimable" otherwise. Registered tests are computed on their registered cells only.
- **Multiplicity:** Holm's step-down procedure within each hypothesis part that has several contrasts (H1a and H2a over five forms; H1b and H2b over two pairs; the go/no-go over each model's contrasts).
- **Exclusions** (every command): refusals, and empty replies (protocol failures). Truncated outputs and episodes that hit the tool-call cap are kept and reported.
- **One-sample rates** (H3): percentile bootstrap over items. **H5a's** Wilson interval counts each item once (its incomplete episodes averaged), which is conservative.

Metric names: `extra_fetch` (called `unnecessary_fetch` before amendment 1) is fetching where no fetch was needed; a check of a truthful last page can be sensible, so it is a cost. `followup_calls` counts the extra calls.

Notes:

- On simulated data, the variational-Bayes mixed model's posterior SDs for fixed effects were about half the item-clustered SEs from the fixed spec. Mean-field VB tends to understate uncertainty, which is why the pre-registration uses the fixed spec, descriptively.
- Both regression specs use the core arm at extent `more_full` by default (`--extent` changes it). Task need is a function of task type, so in the fixed spec its main effect is absorbed by the task-type effects and it enters only as form x page-1-sufficient interactions against the baseline form.
- `fplp figure` puts fetching past a truthful full last page on the x axis when the data include `last_full` cells, and falls back to page-1-sufficient tasks otherwise.
