# Pagination and end-of-results signals in community MCP servers, OpenAPI-to-MCP generators, tool gateways and agent-framework wrappers (checked 2026-10-24)

Scope: what pagination information reaches the model in tool results from layers that sit between Web APIs and LLMs. Official vendor servers (GitHub, Notion, Stripe, Sentry, Supabase, Cloudflare, Atlassian official, modelcontextprotocol/servers) are excluded; another researcher covers them. One vendor-maintained search server (Brave) is included only because the brief named it; it is flagged.

Method: every code-backed entry was read from a shallow clone at the commit SHA in its URL (all clones made 2026-10-24), or from the published PyPI wheel when no public repository holds the code (Arcade toolkits). Doc-backed entries (Composio, Zapier, Stainless, Speakeasy) quote the vendor's current documentation as fetched on 2026-10-24. Popularity comes from the GitHub API (stars, archived flag, last push), pypistats.org and api.npmjs.org (downloads in the 30 days ending 2026-10-22/23), and the official MCP Registry API (registry.modelcontextprotocol.io/v0/servers). No paid API calls were made and no tool was executed against a live API, so every classification is a reading of code or docs, not an observed transcript.

Classification codes used throughout:
- PRESERVE: upstream JSON body reaches the model unchanged (the API's own convention survives).
- EXPLICIT-END: the wrapper writes an explicit end value (false, null, `is_last_page: true`).
- OMIT-END: a continuation field or note appears only when more rows exist; at the end it is absent or an empty string.
- TOTAL-ONLY: only a total count (plus offset) is available for the model to compare.
- NL-NOTE: a natural-language note carries the signal.
- SILENT-CAP: the signal is dropped and a default page size applies; often the tool has no parameter to request the next page.
- AUTO-PAG: the wrapper fetches several or all pages before returning.
- HEADER-LOSS: HTTP response headers (Link, X-Total-Count, X-Next-Page) are not included in the tool result.

## Evidence table: what pagination information reaches the model, per entry

### Takeaway
Across 29 entries (9 community servers, 6 generators, 6 gateways, 8 framework wrapper families), only a minority pass an explicit end value to the model; the most common outcomes are a silently capped page with no continuation signal (frequent in framework wrappers and Gmail wrappers, often at 10 results with no page-token parameter at all) and end-by-omission. Every OpenAPI generator and gateway examined forwards the JSON body but drops HTTP response headers, so APIs that signal pagination only in headers (GitHub Link, GitLab X-Next-Page/X-Total) reach the model as the paper's no-signal condition.

### Inferences
- Entries were chosen for popularity within each category, not sampled at random, so the table describes widely used layers rather than estimating a population rate.
- "End by omission" and "silent cap" together cover most of the tools that do not simply pass a JSON body through. The paper's strongest stop cue (an explicit false/null) appears in wrapper-authored output only in Arcade Jira (`is_last_page: true`), Arcade Gmail search (`next_page_token: null`), gitlab-mcp discussions (`x_next_page: null`) and wherever an upstream body already carries it (Notion JSON via suekou, Slack bodies via ACI/Composio).

### Gaps
- No live tool calls were made, so exact on-the-wire text (for example whether Python `None` serializes as `null` through each MCP SDK, or how Pipedream and Zapier envelope results) is inferred from code, not observed.
- Composio, Zapier MCP and Pipedream's hosted MCP do not publish tool output schemas; their classifications rest on parameter descriptions and platform docs.

## What does the tool result contain: raw upstream JSON, reformatted JSON, or text/markdown?

### Takeaway
Generators and gateways mostly forward the raw JSON body (FastMCP, Stainless legacy, Speakeasy, openapi-mcp-generator, fastapi_mcp, ivo-toby, ACI, ADK RestApiTool, Klavis Jira), while hand-written community servers and framework wrappers usually reformat into reduced JSON, CSV, or plain text and in doing so decide which pagination fields survive.

### Cited Findings

- Body passthrough means the upstream API's convention decides what the model sees. For body-signalled APIs (Notion `has_more`, Slack `response_metadata.next_cursor`, Gmail `nextPageToken`, Stripe-style `has_more`) the generators are neutral carriers. For header-signalled APIs they become lossy (next question).
- jq filtering is a second, model-controlled lossy step: the Stainless description's own example `.results[].name` would return only names and drop `has_more`/`next_cursor` if applied to a list response (inferred; not observed in a transcript).

### Gaps
- Stainless Code Mode output depends entirely on code the model writes; whether models use `for await` auto-pagination or a single page could not be determined from docs.

## How is "more results exist" signalled to the model, if at all?

### Takeaway
Seven mechanisms appear: preserved upstream body fields, a wrapper-written cursor/token field, an extra CSV column, a text line with a token, a natural-language instruction, a total count, and an explicit truncation flag; in a large share of tools there is no signal at all, and header-only upstream signals are never forwarded by any generator or gateway examined.

## How is the END marked?

### Takeaway
End-by-omission dominates among wrappers that signal at all (token, line or note simply disappears, or a CSV cell goes empty); explicit end values appear only where the upstream body already has them or in a few wrappers (Arcade Jira, Arcade Gmail search, gitlab-mcp discussions); silent tools give no end marker at all.

### Cited Findings
- Omitted field: mcp-atlassian adds `next_page_token` only `if self.next_page_token is not None` ([search.py L122-L123](https://github.com/sooperset/mcp-atlassian/blob/0a5d2427144d72f5aade07d4fabd385421cec401/src/mcp_atlassian/models/jira/search.py#L114-L124)); gitlab-mcp search `next_page: nextPage ? ... : undefined` ([index.ts L5573-L5576](https://github.com/zereight/gitlab-mcp/blob/2da8471bff832c58a1d4ae90c25bfb62610fa150/index.ts#L5560-L5577)).
- Omitted line or note: google_workspace_mcp Gmail note and Drive `nextPageToken:` line appear only when a token exists ([gmail_tools.py L1760-L1766](https://github.com/taylorwilsdon/google_workspace_mcp/blob/fcbf5a2ccf80ea2e2877ff56126b97813e1bbb03/gmail/gmail_tools.py#L1760-L1766); [drive_tools.py L315-L317](https://github.com/taylorwilsdon/google_workspace_mcp/blob/fcbf5a2ccf80ea2e2877ff56126b97813e1bbb03/gdrive/drive_tools.py#L315-L317)); suekou Markdown pagination is `""` when `has_more` is false ([markdown/index.ts L201-L208](https://github.com/suekou/mcp-notion-server/blob/efa09a200932ca62b6eda5aa194e654c80cef6d0/src/markdown/index.ts#L201-L213)); ADK Spanner key is set only when the cap is hit ([spanner/utils.py L126-L129](https://github.com/google/adk-python/blob/12c7bed7661ccf942f0f6d3b62bed22a23ea0a85/src/google/adk/tools/spanner/utils.py#L100-L129)).
- Empty string: korotovsky Slack leaves the `cursor` column empty at the end, and the tool says to use it "if not empty" ([server.go L131](https://github.com/korotovsky/slack-mcp-server/blob/b88c0de3f706f4f07337c9eda7133c736d1c9524/pkg/server/server.go#L131-L147)).
- Explicit values: Arcade Jira `{"is_last_page": True}` (arcade_jira 3.1.2 tools/issues.py L585); Arcade Gmail `"next_page_token": next_page_token` where Gmail omits the token at the end (arcade_gmail 4.2.0 tools/gmail.py L683-L689); gitlab-mcp discussions `x_next_page: ... : null` ([index.ts L4899-L4901](https://github.com/zereight/gitlab-mcp/blob/2da8471bff832c58a1d4ae90c25bfb62610fa150/index.ts#L4897-L4923)); suekou JSON passes Notion's `has_more`/`next_cursor` ([response-optimizer.ts L139-L140](https://github.com/suekou/mcp-notion-server/blob/efa09a200932ca62b6eda5aa194e654c80cef6d0/src/tools/response-optimizer.ts#L133-L145)).
- Total vs rows: mcp-atlassian Server/DC and Klavis Jira leave the model to compare `total` with `start_at + len(issues)` (entries 1, 21).
- Instructions about the end, in descriptions: Composio Gmail "Loop calls using nextPageToken until it is absent... resultSizeEstimate is approximate — do not use as a stopping condition"; Composio GitHub "iterate `page` until results fewer than `per_page` are returned" ([Gmail docs](https://docs.composio.dev/toolkits/gmail.md); [GitHub docs](https://docs.composio.dev/toolkits/github.md)).

### Inferences
- Arcade Gmail search's `None` becomes JSON `null` after serialization (inferred from standard Python JSON encoding; Arcade's transport was not inspected), and Arcade Slack's end value is whatever Slack returns, which the Slack API documents as an empty `next_cursor` (inferred; Slack docs not fetched in this session).
- The Composio GitHub instruction is the short-page heuristic, which cannot recognize an exactly full last page, the case the paper's title names: a model that follows it requests one more page and only then sees an empty result. It never causes an early stop, but it spends an extra call on every full last page and offers no stop cue on a full page (inferred from the rule's logic, not observed).
- ADK's flag is set when the row counter reaches the cap without a look-ahead row, so a query returning exactly 50 rows is flagged "likely truncated" although nothing is missing. The wrapper itself cannot tell a full page from the last page, which is why the key says "likely" (inferred from the loop at L117-L129).

### Gaps
- None of the community servers examined uses a `has_more`-style boolean of its own; whether this is general across the long tail of servers could not be measured within this sample.

## Is there a silent default cap, and does the wrapper auto-paginate internally?

### Takeaway
Silent caps are common, with defaults of 5, 10, 20, 25, 30, 50 or 100, and many capped tools offer no parameter to fetch the next page at all, so a perfect reader of pagination signals still could not continue; a smaller set auto-paginates (Airtable, Pipedream GitHub to its cap, Arcade Slack to its limit, LangChain get_issues and get_channel, mcp-atlassian Jira Cloud to `limit`), which makes the model's reading moot for those calls.

Most consequential examples for the paper:
1. Header-only pagination never reaches the model through generators or gateways. All six generators and ACI forward the body only, and Gram's header allowlist excludes Link and X-Total-Count ([proxy.go L72-L83](https://github.com/speakeasy-api/gram/blob/62405e3d1d0645b916bf0fc07779d903a448bc18/server/internal/gateway/proxy.go#L72-L83)). Concrete instances: zereight/gitlab-mcp list_issues (500,422 npm downloads/month, official MCP Registry) returns a bare array of up to 20 issues with a `page` parameter and no signal ([index.ts L2604-L2610](https://github.com/zereight/gitlab-mcp/blob/2da8471bff832c58a1d4ae90c25bfb62610fa150/index.ts#L2604-L2610)); ACI GITHUB__LIST_ISSUES returns 30 issues the same way ([functions.json L737](https://github.com/aipotheosis-labs/aci/blob/ba14b1916eff02b4cd9dcd5ce8ba879d209c7df7/backend/apps/github/functions.json#L737)). These map directly onto the paper's no-signal arm (34% continuation when more rows exist).
2. sooperset/mcp-atlassian Jira on Cloud (6,037 stars; 674,186 PyPI downloads/month) ends by omission and replaces the total with a constant `"total": -1` while dropping Jira's `isLast`; its Confluence search caps at 10 (max 50) with no offset parameter ([jira/search.py L174-L188](https://github.com/sooperset/mcp-atlassian/blob/0a5d2427144d72f5aade07d4fabd385421cec401/src/mcp_atlassian/jira/search.py#L143-L188); [confluence.py L219-L277](https://github.com/sooperset/mcp-atlassian/blob/0a5d2427144d72f5aade07d4fabd385421cec401/src/mcp_atlassian/servers/confluence.py#L219-L277)).
3. Gmail wrappers silently cap at 10 or 25 with no page-token input across LangChain (langchain-community 27.3M and langchain-google-community 11.0M PyPI downloads/month), GongRzhe (archived, 66k npm/month), Klavis, LlamaIndex, Pipedream and Arcade ListEmails, while the Gmail API itself returns `nextPageToken` ([langchain-google search.py L138-L165](https://github.com/langchain-ai/langchain-google/blob/4270e529042450d981f883058706c058e4c2c651/libs/community/langchain_google_community/gmail/search.py#L138-L165)). A full first page is indistinguishable from the whole mailbox result, and the model has no means to continue.
4. Composio's tool descriptions encode both sides of the paper's result: Gmail "Loop calls using nextPageToken until it is absent... resultSizeEstimate is approximate — do not use as a stopping condition" versus GitHub "iterate `page` until results fewer than `per_page` are returned", the short-page heuristic that fails on an exactly full last page ([Gmail docs](https://docs.composio.dev/toolkits/gmail.md); [GitHub docs](https://docs.composio.dev/toolkits/github.md)).
5. Explicit end values exist but are rare and wrapper-specific: Arcade Jira writes `{"is_last_page": True}` (arcade_jira 3.1.2 tools/issues.py L585), an explicit end value of the kind that cut further fetching to 0 to 1% in the paper (which tested `has_more: false`, `next_cursor: null` and `pageInfo.hasNextPage: false`, not this key); ADK Spanner writes `result_is_likely_truncated` only when its 50-row cap is reached, which also fires on an exact 50-row result ([spanner/utils.py L100-L129](https://github.com/google/adk-python/blob/12c7bed7661ccf942f0f6d3b62bed22a23ea0a85/src/google/adk/tools/spanner/utils.py#L100-L129)).

### Inferences
- For the reviewer's "real-world stakes are unmeasured" objection, this survey supports a narrower claim than prevalence: in widely downloaded intermediaries, the signal forms the paper tests do occur (end-by-omission, total-only, NL notes, explicit end values), and the no-signal condition is produced systematically by header loss and silent caps. It does not measure how often agents hit a full last page in practice.
- Because many capped tools lack a continuation parameter, a fair framing is that the intermediary often decides completeness before the model reads anything; the paper's findings apply to the subset that exposes a parameter (gitlab-mcp, ACI, Brave, mcp-atlassian, Slack servers, Composio, Arcade).

### Gaps
- The counts are a reading of 29 popular projects' code and docs on 2026-10-24, not a census; long-tail servers in Smithery, PulseMCP and mcp.so were not sampled, and Smithery/PulseMCP popularity numbers were not collected (only GitHub, PyPI, npm and the official MCP Registry).
- Hosted platforms (Composio, Zapier, Pipedream, Arcade's hosted runtime) may differ from published code or docs; live calls would be needed to confirm their on-the-wire results.
